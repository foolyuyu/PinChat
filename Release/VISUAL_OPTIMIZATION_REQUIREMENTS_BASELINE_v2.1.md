# PinChat 视觉优化需求基线 v2.1（冻结）

状态：已确认、实施中、冻结  
确认日期：2026-09-15  
适用范围：官方 Codex 桌宠比例、图标和铅笔展开交互优化

## 1. 冻结规则

本文件只记录 v2.1 新增视觉优化，不替换或修改 v1.0、v1.1、v2.0 基线。完成 SHA-256 校验并设为只读后不得原地修改；后续变更必须建立更高版本基线。

## 2. 官方桌宠实机观察

在用户明确授权鼠标控制后，于本机官方 Codex 桌宠完成悬停、沿热区移动、铅笔按下及松开后的连续截图观察。截图包含用户界面内容，仅保存在被 Git 忽略的本地临时目录，不进入仓库；以下记录为去标识化测量结果。

- 官方桌宠可见图像约 60 pt 宽，透明点击承载区明显小于 PinChat v2.0 的 140×144 pt 窗口。
- 悬停桌宠后，其下方出现白色圆角工具条；工具条约 120×40 pt，含铅笔、语音波形和通知铃铛三个约 40 pt 的分区，图标本体约 15–16 pt。
- 官方铅笔使用轮廓式“方框与斜向笔尖”造型，线条为中等偏细，不使用实心粗重图标。
- 输入态在鼠标松开后出现：原工具条直接被约 322×42 pt 的横向输入框取代，而不是继续保留铅笔按钮。
- 输入框为白色或浅色半透明材质、约半高圆角、极淡边界和柔和大范围阴影；左侧为小号加号，右侧为浅蓝圆形上箭头。
- 展开反馈在首个约 120 ms 取样时已基本完成；桌宠同步出现轻微侧身姿态变化，没有长时间闪烁、缩放抖动或空白帧。
- 若鼠标直接跳到悬浮工具条坐标，官方界面可能将点击传给下层内容；PinChat 的有效点击区域必须与可见控件一致并阻止点击穿透。

## 3. v2.1 目标比例

用户要求 PinChat 整体图标继续缩小，并允许桌宠和图标本体略小于官方参考。实现目标如下：

- 桌宠图像目标约 52×56 pt，小于官方约 60 pt 的可见宽度；透明桌宠窗口同步缩至约 96×96 pt。
- 空闲态铅笔入口使用官方同类轮廓图标，按钮目标 28×28 pt、图标约 13 pt；材质、细描边与阴影保持克制。
- 打开输入框后立即隐藏铅笔入口；再次点击桌宠、按 `Esc` 或使用快捷键均可关闭输入框，不能出现“展开后无处关闭”。
- 输入条目标约 360×50 pt；加号与发送/停止按钮目标 30×30 pt，图标本体约 12–13 pt，正文约 15 pt。
- 状态卡目标约 410×66 pt；完成卡三个动作按钮目标 28×28 pt，图标本体约 11–12 pt。
- 回答面板标题栏按钮目标 24×24 pt、图标本体约 12 pt；追问发送/停止按钮目标 30×30 pt。
- 图标选型统一使用与官方相近的 SF Symbols：`square.and.pencil`、`plus`、`arrow.up`、`stop.fill`、`arrow.up.right`、`checkmark`、`chevron.down/up`、`xmark`。

## 4. 交互与视觉约束

- 桌宠、入口按钮、输入条和状态卡必须形成同一垂直锚点；输入条或状态卡出现时替代入口按钮，并贴近桌宠，不留下大块透明空白。
- 展开采用快速横向揭示与轻微淡入，目标时长 0.16–0.18 秒；收起目标时长约 0.13 秒。
- 所有可见按钮的命中区不得小于其可见背景，不得把点击传递给后方应用。
- 继续保留透明窗口、跨 Space、普通全屏置顶、拖动跟手、透明帧过滤和系统浅色/深色适配。
- 不伪造官方未接入的语音与通知功能；PinChat 只呈现本轮实际可用的铅笔入口。
- 不提交官方截图、用户对话内容或账号信息；官方 WebP 仍按 v2.0 规则在运行时缓存。
