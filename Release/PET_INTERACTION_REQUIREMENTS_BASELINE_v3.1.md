# PinChat 桌宠输入交互需求基线 v3.1（冻结）

状态：已确认、实施中、冻结  
确认日期：2026-09-16  
适用范围：Codex 桌宠、输入框与展开回答窗口之间的微交互

## 1. 冻结规则

本文件只记录 v3.1 新增范围，不修改 v1.0 至 v3.0 的冻结基线。生成 SHA-256 校验并设为只读后不得原地修改；后续变更必须建立更高版本基线。

## 2. 核心目标

- 进一步对齐本机官方 Codex 桌宠在输入期间的反馈，使桌宠、文字插入光标与输入界面形成连续互动，而不是相互独立的静态元素。
- 用户打开并使用输入框时，桌宠应朝向正在闪烁的键入光标，而不是鼠标指针；展开回答窗口可继续输入时保持同样反馈。
- 交互必须使用官方绘制的方向姿态，不旋转整张机器人图，不改变既有桌宠尺寸、透明承载区和窗口吸附规则。

## 3. 方向姿态规则

- 使用官方 1536×2288、8×11 帧图集：前 9 行沿用现有基础动画，第 10、11 行提供 16 个方向姿态。
- 方向顺序按正上方 0° 起，每 22.5° 一档顺时针排列；索引 0 至 7 位于第 10 行，索引 8 至 15 位于第 11 行。
- 通过原生文本编辑器读取当前选区的 `firstRect`，以桌宠窗口中心和键入光标的屏幕位置计算方向。macOS 坐标中正上、正右、正下、正左分别映射为 0°、90°、180°、270°。
- 键入光标位于中心 1 pt 死区内时回到普通待机姿态，避免无意义方向。
- 只有输入条或回答窗口中的文本栏真正获得键入焦点时才采样；文本增长、换行、点击或方向键移动插入点以及窗口移动后都应更新方向。
- 输入框失焦、面板收起或应用切换后立即停止注视并恢复基础姿态；普通状态约 30 Hz 读取光标，系统开启“减少动态效果”时降至约 10 Hz。

## 4. 动画优先级与衔接

- 拖动桌宠时，跳跃/拖动姿态优先于方向姿态；拖动结束且文本栏仍具有键入焦点时恢复朝向插入光标。
- 失败及其他明确瞬时状态优先显示自身动画，不被方向姿态覆盖。
- 待机、工作和完成反馈允许使用方向姿态，使输入与流式回答期间仍保持视线互动。
- 输入框展开并自动聚焦后立即按插入光标位置选择姿态；关闭或失焦时立即回到基础动画。
- 维持现有状态卡向中间收起、输入框横向展开、全屏置顶、多屏定位和任务展示逻辑。

## 5. 素材与兼容

- 不把 ChatGPT/Codex 官方 WebP 二进制提交到仓库或源码压缩包。
- ChatGPT 桌面应用存在时，只读其 `app.asar` 目录，动态查找最新 `codex-spritesheet-v*.webp`，只接受校验为 1536×2288 的方向图集，并保存至 PinChat 缓存。
- 不修改 ChatGPT 应用及其资源；官方资源不可用或格式变化时，继续兼容 1536×1872、8×9 的既有图集和离线矢量后备形象，基础功能不得失效。
- 缓存只位于 `~/Library/Caches/PinChat/Pets`，不进入 Git 或 Release 源码包。
