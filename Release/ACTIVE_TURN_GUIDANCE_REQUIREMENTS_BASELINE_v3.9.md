# PinChat v3.9 运行中补充引导需求基线（锁定稿）

锁定日期：2026-09-18（Asia/Shanghai）

本文件记录用户对 v3.8“补充”位置与语义的澄清，并取代 v3.8 中“桌面任务观察卡预填补充”的实现方式。v1.0 至 v3.8 其他冻结需求继续有效；本文件不得回改既有基线，只允许后续版本追加。

## 1. 正确作用范围

- “补充”属于 PinChat 自己发起且仍在思考的当前任务卡，不属于只读的 Codex Desktop 任务观察列表。
- 桌面任务观察列表继续负责展示主应用任务状态；整行点击打开对应 Codex 任务，不再放置只能预填、不能即时引导当前 turn 的伪补充入口。

## 2. 官方式运行中控制

- PinChat 当前任务进入真实活动 turn 后，状态卡右侧同时显示“补充”和“停止”两个按钮。
- 点击补充按钮时，状态卡在原位置向下展开紧凑输入区并自动聚焦；再次点击补充按钮可关闭输入区。
- 输入内容提交后必须调用当前 PinChat App Server 连接的 `turn/steer`，参数包含原 `threadId`、当前 `expectedTurnId` 和补充文字输入。
- 补充不得新建线程、不得等待原任务结束、不得仅打开 Codex 或只预填输入框。
- 提交成功后收起补充输入区，当前任务继续运行；提交失败时保留输入并显示真实错误。
- 当前 turn 尚未建立、正在提交补充或任务已经结束时，不得重复提交。

## 3. 布局与状态

- 未展开时维持现有紧凑任务卡尺寸。
- 展开时只增加一行输入区，不改变任务标题、当前状态和停止按钮的语义。
- 任务结束、失败、停止或整个小窗关闭时，补充输入区自动收起并清空草稿。
- 卡片尺寸变化继续遵循桌宠位置自动向上或向下展开，不得超出当前屏幕可见区域。

## 4. 验收标准

- PinChat 发出一项持续运行的任务后，活动 turn 就绪时补充按钮可用。
- 输入一条引导并提交，App Server 收到 `turn/steer`，且 `expectedTurnId` 与当前 turn 完全一致。
- 原任务不中断、不新建对话，并继续按补充后的要求执行。
- 停止按钮仍调用真实 `turn/interrupt`。
- Codex Desktop 只读任务列表不再显示错误位置的预填补充按钮。
- 自动测试、Debug/Release 构建、签名及 v1.0 至 v3.9 全部冻结需求校验通过。
