## 回答窗切换输入框验证

- 回答窗小笔点击时读取 AppKit 当前鼠标屏幕坐标，生成中心与点击点完全一致的 28×28 pt 收拢目标。
- 回答窗使用 0.24 秒缓入缓出缩放并同步淡出；原回答内容保持到动画结束，之后才创建新会话。
- 动画结束后回答窗恢复原始尺寸并隐藏，再从桌宠锚点运行既有小输入框横向展开动画。
- 动画期间临时解除回答窗最小尺寸限制，并屏蔽程序化移动和缩放的持久化回调，不会污染下次窗口尺寸。
- 切换状态设置重复触发保护，避免连续点击启动多个新会话或交叠动画。
- 新增测试验证收拢尺寸、点击点中心和动画时长。

## 官方完成桌宠验证

- 本机官方 Codex 图集包含独立的第 9 行 `review` 动画，画面为桌宠微笑、举手和轻量庆祝；无需生成或下载第三方素材。
- 官方应用实现明确将未查看的成功通知映射为 `mascotState: review`，状态文案为 `Ready`，与 PinChat 的未查看完成回执语义一致。

- 完成回执的持续与查看逻辑没有改变：任务列表真正显示前持续循环，显示一次后恢复普通桌宠，任务卡继续独立遵循查看后 30 秒规则。

## 统一任务流程验证

- 桌宠小输入框发送前强制建立新会话；完整回答窗口中的追问不触发新建，因此继续原 Codex 线程。
- PinChat 当前交互任务与只读活动观察结果在界面层按线程 ID 合并；相同线程只出现一次，正在生成的实时状态覆盖轮询滞后的状态。
- 活动观察通道继续只读运行，同时明确纳入 PinChat 已创建的线程；底层写入通道与观察通道没有合并，避免重新引入 active writer 冲突。
- 小输入框发送后不再产生独立过程卡；悬停桌宠显示统一任务列表。真实首条回答仍触发简单对话自动展开，执行型事件不自动展开。
- 已展开回答窗不再被快捷键、桌宠点击、状态卡收回、任务完成、工作类型判断、Codex 跳转或应用失焦关闭；仅窗内 `×` 执行关闭。
- 任一未查看的完成回执会持续显示官方 `review` 完成姿态；统一任务列表实际显示一次后恢复普通桌宠，任务卡的 30 秒查看后回收规则保持独立。
- 新增测试覆盖统一列表去重与实时状态优先，以及完成回执在真正查看前后的持久提示策略。

- 行背景改为无独立阴影的连续矩形，整个任务列表统一裁切到外卡片相同的 18 pt 圆角，因此首末行自然贴合边缘。
- 任务卡整体悬停时，以完全相同的 18 pt 轮廓叠加弱白色渐变、极淡强调色反射和 0.75 pt 边缘光。
- 已完成任务确认按钮使用与行内容相同的首末留白布局，保持垂直对齐。
- 桌宠与卡片的 3 pt 原始距离、窗口层级和阴影承载尺寸均未修改。

## 点击外部自动收回验证

- 输入小窗在 PinChat 应用失去激活后等待当前鼠标操作结束，再按松开位置决定是否调用统一收回流程；普通点击桌面或其他应用无需再次操作桌宠。
- 监听的是应用级失去激活而不是输入框失焦，因此附件弹出菜单和 PinChat 自己打开的系统文件选择器不会让输入条误收回。
- 从 Finder 连续拖动文件时，外部失活发生在按下阶段；PinChat 会等鼠标释放，并在落点位于输入小窗时保留窗口，让既有原生拖放接收器正常加入附件。
- 桌宠点击、`Esc` 和快捷键关闭输入条均复用同一中心收拢动画；状态卡、任务生成和回答窗口维持原有独立关闭逻辑。
- 收拢后的窗口保持原水平中心、垂直位置和高度，只将宽度压缩至 8 pt 并同步淡出，动画完成后恢复完整 frame 与透明度。
- 动画修订号使旧完成回调在输入条已经重新展开时失效，避免快速操作后窗口被二次隐藏。
- 新增测试验证中心收拢几何不会造成横向偏移或垂直跳动。

## 运行中补充引导验证

- PinChat 自己发起的任务建立真实活动 turn 后，当前任务卡同时显示“补充”和“停止”；活动 turn 尚未就绪时补充按钮保持禁用。
- 点击补充后，原卡片向下展开紧凑输入栏并自动聚焦；再次点击、任务结束、停止或关闭窗口时都会收起并清理草稿。
- 提交补充会在当前 App Server 连接上调用 `turn/steer`，参数使用原线程的 `threadId`、当前 turn 的 `expectedTurnId` 和补充文字，不新建任务，也不等待原任务结束。
- `turn/start` 成功后先在服务队列记录活动 turn，再通知界面开放补充，消除了按钮已可点击但服务端尚未保存 turn 的竞态。
- 提交成功后输入栏收起且原任务继续；失败时输入内容保留，并显示服务端返回的真实错误。
- 新增测试验证补充请求准确绑定当前线程和当前 turn；既有停止按钮继续使用真实中断链路。
- Codex Desktop 自己持有的任务仍由独立只读观察通道展示，整卡点击打开相应任务，不再显示不能即时引导当前 turn 的预填式补充入口。

## 任务卡交互整理验证

- 当前 PinChat 问答点击 `✓` 时，同步确认相同线程在桌面观察通道中的完成回执；若观察回执稍晚到达，持久化的待确认线程标记会在下一次同步时消费该回执，避免再次悬停返场。
- 确认只针对当前对话线程，不会清除同时存在的其他 Codex 完成任务。
- 桌面任务整行均可打开对应 Codex 任务，拥有轻量悬停与按下反馈；重复的右侧斜向箭头已删除。
- v3.8 曾采用桌面任务深链预填式补充；该入口现已由 v3.9 的 PinChat 当前活动 turn 真实 `turn/steer` 引导取代，桌面任务观察卡恢复为只读状态与整卡打开。
- 回答面板顶部左侧图标、标题和吸附状态标签已删除，仅保留右侧新建与关闭操作。
- 官方桌宠的一键停止通过 Codex Desktop 进程内部 active writer 执行；独立 PinChat 观察进程无法取得该 writer，因此没有添加假暂停按钮，也没有引入需要系统辅助功能授权的模拟点击。

## 完成任务确认回收验证

- PinChat 当前问答完成卡左侧 `✓` 继续执行整卡确认：结束当前小窗对话并立即关闭紧凑窗口。
- 桌面任务悬停卡中，已完成项目左侧的静态图标已改为原生悬停反馈按钮；点击后只确认目标完成回执，不打开 Codex、不新建对话、不影响其他任务。
- 状态列表仍有其他任务时只移除目标行并调整面板高度；最后一项被确认后复用稳定的状态卡退场动画整体收起。
- 普通“已查看”与主动“已确认”使用独立持久化记录：前者继续满足完成满 30 秒后隐藏，后者立即过滤且重启后不会重新出现。
- 同步完成回调会再次应用当前确认集合，覆盖点击发生在轮询途中的竞态，避免已确认任务闪回。
- 新增测试覆盖主动确认只过滤目标完成回执，同时保留其他完成任务和进行中任务。

## 悬停退场闪帧修复验证

- 根因不是完成任务本身的 30 秒筛选，而是状态卡开始执行 0.13 秒收起动画时过早将 `statusContext` 清空；仍可见的同一窗口因此改为渲染当前对话完成状态。
- 已查看回执又在动画开始前立即触发一次桌面任务刷新，使内容切换更容易与退场帧同时出现。
- 修复后，退场动画期间继续保持桌面任务上下文和原显示内容；`orderOut` 完成后才清空上下文、提交已查看回执并刷新过滤结果。
- 收起动画进行中拒绝新的悬停收起请求，避免多次 completion 交错造成闪烁或状态回写。
- 既有规则保持不变：完成项必须已经展示过，并且完成时间超过 30 秒，之后才从下一次悬停列表中移除。

## 截图拖放修复验证

- 紧凑输入条与展开回答后的追问区共用同一 macOS 原生拖放接收器和附件标签组件。
- 接收器优先解析 Finder 提供的本机文件 URL；同时接受 PNG、JPEG、HEIC、TIFF 等图片数据，解决截图缩略图或图片应用未提供直接 URL 时无法加入的问题。
- 原始图片数据写入 `~/Library/Caches/PinChat/Attachments` 下的唯一文件，发送时继续使用 Codex 原生 `localImage` 输入，不修改拖拽来源。
- 回答追问区允许仅附件发送，也允许文字与附件一起发送；发送后清空本轮附件标签并继续保持回答窗口展开。
- 新增测试覆盖 macOS URL/NSData 文件表示、远程 URL 拒绝、拖入图片缓存及图片附件类型识别。

## 原生文本快捷键与附件拖放验证

- 应用启动时安装不可见但完整的 macOS 标准编辑菜单，由系统响应 `⌘A` 全选、`⌘C` 复制、`⌘V` 粘贴、`⌘X` 剪切、`⌘Z` 撤销和 `⇧⌘Z` 重做；输入条与回答追问框共用同一原生响应链。

- 拖入经过输入条时显示轻量强调色高亮，离开或放下后立即恢复，不增加常驻边框。
- 拖放与 `+` 文件选择器调用同一附件合并逻辑；标准化路径后过滤既有附件、同批重复项，并保留首次加入顺序。
- 新增测试覆盖标准编辑菜单快捷键映射，以及文件、文件夹、重复路径和远程 URL 的附件合并行为。

## Codex 权限跟随验证

- 本机 Codex Desktop 的共享状态当前为 `agent-mode-by-host-id.local = full-access`，同时 `permission-selection-by-host-id:local` 为 `agent-mode / full-access`；PinChat 解析结果为“完全访问”。
- PinChat 已移除输入框权限菜单和设置页权限选择器，不再读取或写入旧的 `pinChatPermissionModeV1` 偏好。
- 每次展开输入框及发送前都会刷新共享状态；新建、恢复、每轮 `turn/start` 和交接前恢复使用同一配置。
- 完全访问会同时发送 `approvalPolicy: never`、线程级 `sandbox: danger-full-access` 与轮次级 `sandboxPolicy.type: dangerFullAccess`，避免旧线程或下一轮退回工作区审批。

## PinChat 对话与 Codex 交接

- v3.0 每轮从“判断中”开始；纯回答出现时自动展开回答面板，执行型事件出现时保持或恢复紧凑进度卡。
- 类型判断使用 App Server 的真实 item 与 request 事件，不扫描问题关键词；同一工作轮次不会因最终文字回答再次自动展开。
- 自动展开只发生在状态首次从“判断中”进入“对话”时，用户手动关闭后不会被后续流式文字反复打开。
- PinChat 自己发起请求后的思考/完成状态卡、回答展开、拖动、缩放、关闭、继续追问和 Markdown 排版保持不变。
- v2.3 使用独立对话 App Server 处理账号、提问、流式回答和当前线程同步；独立活动观察 App Server 只读处理 `thread/list` 和桌面任务状态。
- 对话完成卡的 `↗` 会先执行 `thread/unsubscribe`，随后彻底终止并等待对话 App Server 退出，最后使用 `codex://threads/<thread-id>` 打开同一任务。
- Codex URL 只在对话进程退出完成后打开，消除了 App Server 无订阅宽限期造成的“已在另一个应用中打开”竞争。
- 交接后活动观察 App Server 保持运行；再次打开 PinChat 输入框时仅按需启动新的对话通道，不恢复已交接线程。
- 若 Codex URL 打开失败，PinChat 会重启对话通道并保留原会话，允许继续使用。
- 桌面任务悬停卡的 `↗` 可直接打开对应 Codex 任务；该路径只导航，不修改任务。
- Release 实机验证：PinChat 启动并连接后具有两个独立子 App Server；真实提问完成并点击 `↗` 后，对话子进程退出，仅保留一个活动观察子进程。
- 同一个已交接任务随后由 Codex 接受第二轮消息并无错误完成，证明原任务 ID 可继续使用且不存在 PinChat 活跃写入者占用。

## 安全与边界

- PinChat 不再定义自己的默认权限；它只读跟随 Codex Desktop 为本机 host 保存的当前权限选择，不写入或修改 Codex 配置。
- Codex 选择“询问批准”时，越界命令、文件修改和权限扩展由小窗请求用户决定；选择“自动审查”时使用官方 `auto_review` reviewer；选择“完全访问”时使用 `danger-full-access + never`。
- 输入框与设置页不再提供 PinChat 私有权限选择器，避免同一台机器出现两套互相矛盾的权限状态。
- 权限表示可用能力上限，不要求模型对普通问答调用文件或命令工具；附件选择也不自动授予任意写权限。
- 完全访问仍受 macOS TCC 和完全磁盘访问权限约束，PinChat 只提供打开系统设置的入口，不自动更改系统隐私授权。
- 仓库和应用包不内嵌官方 WebP 二进制素材；运行时优先读取 Codex 缓存，其次读取 PinChat 缓存或下载官方资源。
- 本地任务索引与 rollout 仅读取，不写入、不删除、不改变 Codex 设置。
- 全屏置顶指普通 macOS 全屏 Space，不包括锁屏、登录界面、系统安全窗口或受保护 DRM 画面。
- 本轮不含语音、其他 AI API、Developer ID 签名、公证或 App Store 上架。
