# PinChat 3.15 统一任务流程需求基线（已锁定）

锁定日期：2026-09-18（Asia/Shanghai）

本文件记录用户已确认的 v3.15 需求。实现期间不得自行修改需求范围；后续变化必须作为新的版本需求另行记录。

## 1. 统一任务模型

1. 桌宠小输入框每次发送都必须创建一个新的 Codex 对话，并作为普通 Codex 任务进入统一任务队列。
2. 小输入框任务与 Codex 桌面端任务使用同一套任务列表、状态和悬停展示，不得再分别生成两个过程框。
3. 小输入框发起且尚未完成的任务也必须能在用户悬停桌宠时查看。
4. 完整回答窗口中的继续提问必须沿用当前 Codex 对话，不得新建任务。

## 2. 发送与任务类型判断

1. 小输入框发送后立即收起，任务进入判断/思考状态，桌宠切换为工作姿态。
2. 任务类型必须依据 App Server 的真实事件判断，不得扫描用户问题关键词：
   - 第一条正式文字回答出现且此前没有执行事件时，识别为简单文字对话，并立即展开置顶回答窗口，不等待整轮完成。
   - 命令、文件修改、工具调用、审批、检索等执行事件出现时，识别为工作任务，不自动展开回答窗口。
3. 小输入框任务本质上仍是 Codex 任务；任务状态、完成回执和在 Codex 中打开的目标均以真实线程为准。

## 3. 回答窗口持久规则

1. 自动展开的回答窗口必须持续置顶。
2. 失去焦点、点击桌面、任务完成、任务被识别为工作类型、悬停结束、状态卡收回、再次展开小输入框或使用全局快捷键，均不得关闭已经展开的回答窗口。
3. 回答窗口只能由用户点击窗口内的 `×` 主动关闭。
4. 回答窗口仍需支持拖动、缩放、附件和继续提问；拖离桌宠后保持为独立置顶窗口。

## 4. 完成提示与回收

1. 任一被跟踪任务完成后，桌宠持续显示明显的灯泡/灵光完成标记，不按时间自动消失。
2. 用户把鼠标停留在桌宠上并真正看到统一任务列表一次后，对应完成标记才消失。
3. 查看完成标记不等于立即删除任务卡。任务卡继续遵循既有规则：完成任务必须已经展示给用户，并且完成满 30 秒后才自动回收。
4. 用户主动点击完成任务的 `✓` 时，仍可立即确认并回收该任务。

## 5. 验收标准

1. 连续两次从桌宠小输入框发送，会产生两个不同的 Codex 线程。
2. 小输入框任务和桌面端任务可同时出现在同一悬停列表中，相同线程只显示一次，当前交互状态优先于轮询滞后的观察状态。
3. 简单对话在首条正式回答出现时自动展开回答窗口；执行型任务不自动展开。
4. 回答窗口展开后，除点击其 `×` 外的常见交互都不能使其消失。
5. 回答窗口内追问继续原线程。
6. 完成灯泡在未查看时持续存在；首次真正展示任务列表后消失，任务卡仍按查看与 30 秒规则保留或回收。
