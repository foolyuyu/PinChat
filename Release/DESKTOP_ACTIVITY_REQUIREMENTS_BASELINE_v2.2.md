# PinChat 桌面任务联动需求基线 v2.2（冻结）

状态：已确认、实施中、冻结  
确认日期：2026-09-15  
适用范围：桌宠入口、悬停状态卡、Codex 桌面端任务状态同步与过渡动画

## 1. 冻结规则

本文件只记录 v2.2 新增交互，不替换或修改 v1.0、v1.1、v2.0、v2.1 基线。完成 SHA-256 校验并设为只读后不得原地修改；后续变更必须建立更高版本基线。

## 2. 用户确认的核心流程

- 删除机器人下方的独立铅笔入口；点击机器人本体即等效于原铅笔按钮，直接打开快速输入框。
- 鼠标移入机器人并短暂停留后，在机器人旁展开一张简短任务状态卡。
- 状态卡同步最近活跃的本机 Codex 桌面端任务，至少明确显示“正在思考”或“已完成”，并展示简短任务标题。
- 状态卡是任务进程摘要，不增加历史会话列表，也不复制一个 Codex 主页面。
- 当悬停状态卡已展开时点击机器人，状态卡先向自身中间横向收起，随后输入框沿相同锚点紧接展开，形成连续替换动画。
- 鼠标移出机器人和状态卡后，悬停状态卡自动收起；从机器人移动到状态卡时不得闪烁或立即消失。
- PinChat 自己发起请求后的思考/完成卡、回答展开、追问、在 Codex 中打开等既有能力继续保留。

## 3. 状态同步规则

- 使用本机 Codex App Server 的任务索引获取最近活跃任务，不接第三方 API、不要求 API Key，也不消耗额外模型调用。
- 结合 Codex 本机任务记录中的 `task_started`、`task_complete`、`turn_aborted` 等事件判断实时状态；不得仅用固定延时伪造完成状态。
- 状态轮询应低频、只读，不能中断、接管或修改 Codex 桌面端正在执行的任务。
- 当任务正在等待审批或用户输入时，仍视为进行中，并以清晰状态文案提示。
- 无可用任务时可显示 Codex 就绪空态；同步暂时失败时保留最近一次有效摘要，不能造成桌宠闪烁。

## 4. 视觉与动效约束

- 桌宠可见尺寸继续沿用 v2.1 的约 52×56 pt，不因删除铅笔入口而放大。
- 移除铅笔后缩减桌宠透明承载区下方冗余，使可点击区域与可见机器人更贴合。
- 悬停触发采用短暂停留阈值，避免鼠标掠过时频繁弹窗；展开、收起保持克制、快速。
- 状态卡与输入框沿同一桌宠锚点智能向上或向下放置，并继续支持普通桌面与全屏 Space 置顶。
- 状态卡向中间收起后再展开输入框；两段动画之间不得出现长时间空白、重叠或点击穿透。

## 5. 验收与交付

- 为任务事件状态归约、桌面任务摘要、删除铅笔后的尺寸约束和悬停时序增加自动化测试。
- 完成 Swift 测试、Release 构建、Info.plist、签名和全部冻结基线哈希校验。
- 实机检查：悬停出现、跨越机器人与卡片不闪烁、移出收起、点击连续替换、拖动、全屏置顶及桌面任务状态更新。
- 更新 README、验证报告、应用包和源码压缩包；完成新的本地 Git 提交，除非用户另行要求，不自动推送远端。
