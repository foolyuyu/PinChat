# PinChat v3.5 截图拖放修复需求基线（锁定稿）

锁定日期：2026-09-18（Asia/Shanghai）

本文件记录 PinChat v3.5 的增量修复需求。v1.0 至 v3.4 已冻结需求继续有效；本文件不得回改既有基线，只允许后续版本追加。

## 1. 问题定义

- v3.4 仅通过 SwiftUI `URL` Transferable 接收拖放，部分 Finder 截图、系统截图缩略图和图片应用提供的是原始图片数据或不同的文件 URL 表示，因此无法生成附件。
- v3.4 只在最初的紧凑输入条注册拖放；回答展开后的“继续提问”区域没有附件状态与拖放目标。

## 2. 修复要求

- 紧凑输入条和回答追问区都必须接受拖放。
- 必须兼容 macOS 本机文件 URL 的 URL、NSURL 与 Data 表示。
- 必须接受符合 `UTType.image` 的原始图片数据；当没有可用源文件路径时，将数据写入 PinChat 自有缓存后加入附件。
- 缓存文件使用唯一名称并保留合适图片扩展名，不覆盖现有文件。
- 远程 URL 不得被当作本机附件。
- 回答追问区应显示可移除附件标签，并允许仅附件发送或文字与附件一起发送。

## 3. 安全与边界

- 不移动、删除或改写用户拖拽的原文件。
- 不自动下载远程 URL，不读取未被用户拖入的文件。
- 缓存仅用于用户明确拖入但没有稳定文件路径的图片。
- 保持 Codex 权限跟随、原生图片输入、标准编辑快捷键和现有视觉风格。

## 4. 验收标准

- 从 Finder 拖入截图文件，紧凑输入条出现图片附件标签。
- 将截图缩略图或图片应用中的图片拖入时，即使只提供图片数据，也能生成本机缓存附件。
- 回答展开后拖入截图，追问区出现附件标签并可发送。
- 重复本机路径继续去重，远程 URL 继续拒绝。
- 自动测试、Debug/Release 构建、签名以及 v1.0 至 v3.5 基线校验全部通过。
