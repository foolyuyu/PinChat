# PinChat 附件与无透明边框需求基线 v2.4（冻结）

状态：已确认、实施中、冻结  
确认日期：2026-09-15  
适用范围：紧凑输入框、状态卡表面、附件选择与 Codex turn 输入

## 1. 冻结规则

本文件只记录 v2.4 新增范围，不修改 v1.0 至 v2.3 的冻结基线。生成 SHA-256 校验并设为只读后不得原地修改；后续变更必须建立更高版本基线。

## 2. 无透明矩形边框

- 去除输入框和状态卡外围由额外透明 padding 形成的矩形承载区。
- 紧凑窗口的可见圆角表面必须贴合窗口边界，不得在四周露出可感知的透明方框、灰色描边或叠套边框。
- 输入框改用不透底的系统窗口背景，避免下方页面文字透过后形成廉价玻璃框观感。
- 保留克制的柔和阴影、圆角、展开动画和全屏置顶能力。

## 3. 官方式加号附件入口

- 登录并连接后，输入框左侧 `+` 必须是可操作菜单，不再显示“后续版本提供”的占位提示。
- 菜单提供“添加文件和文件夹…”，“添加照片…”和“截屏…”三项，与官方 Codex 的 add files、add photos、capture appshot 能力对应。
- 文件和照片选择支持多选；照片通过 App Server `localImage` 输入发送。
- 普通文件和文件夹以用户明确选择的绝对路径作为本机上下文发送，PinChat 不复制、不上传或修改源文件。
- 截屏使用 macOS 交互式区域/窗口选择，结果保存至 PinChat 缓存并作为本地图片附件发送。
- 已选择附件在输入框上方以紧凑标签显示，可单独移除；允许仅发送附件而不输入正文。
- 发送完成后清空当前附件；隐藏再展开输入框时，尚未发送的附件继续保留。

## 4. 安全与兼容

- 文件选择完全由用户发起；PinChat 不扫描目录，不自动附加文件。
- 延续只读 sandbox 和 `never` 审批策略；普通文件仅供 Codex 按需读取，不能被 PinChat 或模型修改。
- 老版本 `sessions.json` 必须继续可解码；附件元数据使用兼容的可选字段。
- v2.3 双 App Server 与无冲突交接行为不得回退。

## 5. 验收与交付

- 自动化测试覆盖图片/普通文件输入映射、附件-only 提交、附件持久化兼容和紧凑表面无外圈尺寸。
- 实机验证 `+` 菜单、文件/照片多选、移除、交互式截屏、发送后清空及窗口动态增高。
- 完成 Swift 测试、Xcode 构建、Release 构建、签名和全部冻结基线哈希校验。
- 应用版本升级为 0.2.4（构建号 6），更新 README、验证报告、应用包、源码压缩包并创建本地 Git 提交；本轮不自动推送远端。

## 6. 官方依据

官方 Codex 桌面资源声明 `composer.addFiles`、`composer.addPhotos` 与 `composer.captureAppshot` 命令。官方 App Server 文档规定 `turn/start.input` 支持 `text`、远程 `image` URL 和 `{ "type": "localImage", "path": "..." }` 本地图片输入：[Codex App Server - Turns](https://learn.chatgpt.com/docs/app-server#turns)。
