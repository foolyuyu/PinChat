# PinChat v3.13 官方光标注视与待机修正需求基线（锁定稿）

锁定日期：2026-09-18（Asia/Shanghai）

本文件修正 v3.12 中对官方桌宠注视动作的错误理解。v1.0 至 v3.12 其他冻结需求继续有效；本文件只覆盖 v3.12“逐格转向”的错误规则，不回改旧基线。

## 1. 官方实现依据

- 官方 Codex v2 桌宠图集为 8×11；第 10、11 行提供 16 个低头注视帧。
- 官方根据桌宠中心与真实文字插入光标的夹角，以 22.5° 为一档直接选择对应帧。
- 官方不会沿 16 个方向逐格旋转；PinChat 必须删除 v3.12 的 50 毫秒逐格过渡。
- 官方在快速输入布局变化后等待两个动画帧完成焦点确认，避免使用未稳定的输入布局。

## 2. 光标注视

- 输入框获得焦点后，PinChat 持续读取原生文本编辑器的插入光标屏幕坐标。
- 输入、移动光标、换行和改变选择位置后，重新计算“桌宠中心 → 插入光标”的方向并直接显示对应低头帧。
- 不使用鼠标指针，不在方向帧间插值，也不播放转圈式过渡。

## 3. 待机恢复

- 输入框关闭或失去文本焦点后，桌宠立即退出低头注视姿态并从待机首帧开始。
- 官方待机 6 帧时长依次为 1.68、0.66、0.66、0.84、0.84、1.92 秒。
- 不得按全局时间随机落入某个待机帧，以免恢复待机的一刻出现一次跳动。
- 历史回答继续不触发持续挥手。

## 4. 范围边界

- 本版仅修正光标注视和待机恢复；统一任务展示流程继续停留在确认稿，不提前实现。

## 5. 验收标准

- 桌宠低头方向随文字插入光标变化，姿态与官方 16 向公式一致。
- 打开输入框时不再出现绕方向转头，关闭输入框时不再先跳一下再待机。
- 自动测试、Debug/Release 构建、签名及 v1.0 至 v3.13 全部冻结需求校验通过。
