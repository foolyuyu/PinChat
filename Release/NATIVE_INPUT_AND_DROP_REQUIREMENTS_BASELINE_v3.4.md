# PinChat v3.4 原生输入与拖放需求基线（锁定稿）

锁定日期：2026-09-17（Asia/Shanghai）

本文件记录 PinChat v3.4 的增量需求。v1.0 至 v3.3 已冻结需求继续有效；本文件不得回改既有基线，只允许通过后续新版本基线追加需求。

## 1. 产品目标

PinChat 作为 Codex Desktop 的 macOS 置顶输入扩展，应遵循用户已形成的系统输入习惯，并允许用户像在官方输入框中一样直接拖入本机文件或文件夹。

## 2. macOS 标准编辑快捷键

- 紧凑输入条与完整回答窗口的追问文本框必须支持 macOS 标准编辑命令。
- 至少支持：`⌘A` 全选、`⌘C` 复制、`⌘V` 粘贴、`⌘X` 剪切、`⌘Z` 撤销、`⇧⌘Z` 重做。
- 快捷键必须通过 AppKit 标准菜单与响应链实现，不单独监听键盘，不申请输入监控或辅助功能权限。
- 快捷键只作用于当前获得焦点的文本编辑器，不改变全局快捷键 `⌥⇧Space` 与 `Esc` 收起逻辑。

## 3. 文件与文件夹拖放

- 用户可从 Finder 将一个或多个本机文件或文件夹拖入紧凑输入条的任意位置。
- 拖放目标进入时显示轻量强调色高亮；离开或完成放下后恢复原外观，不新增常驻边框。
- 拖放附件与 `+` 文件选择器进入同一附件队列，继续以可移除标签展示，并触发输入条已有的附件高度变化。
- 同一路径已经存在或在同一批拖入中重复时只保留一项，并保持首次加入顺序。
- 只接收本机文件 URL；网页或其他远程 URL 不应被误当作本机附件。
- 文件与文件夹仅作为用户明确选择的本机上下文交给 Codex，不复制、移动、修改或删除源内容。

## 4. 兼容与边界

- 保持 macOS 14 及以上系统要求。
- 保持无 Dock 图标、置顶、全屏 Space、Codex 权限跟随与既有附件发送逻辑。
- 本版本不新增剪贴板历史、全局键盘监听、自动读取剪贴板或远程 URL 下载。

## 5. 验收标准

- 输入任意文本后，`⌘A` 能全选，`⌘C` 后可复制，`⌘V` 可粘贴，`⌘X` 可剪切，撤销与重做正常。
- 从 Finder 拖入单个文件、多个文件或文件夹后，输入条出现对应附件标签。
- 重复拖入同一路径不会生成重复标签；拖入远程 URL不会添加附件。
- 自动测试覆盖编辑菜单关键快捷键与附件合并去重规则。
- Debug、Release 构建、签名及 v1.0 至 v3.4 全部冻结需求校验通过。
