# PinChat 多任务与官方能力菜单需求基线 v2.5（冻结）

状态：已确认、实施中、冻结
确认日期：2026-09-15
适用范围：桌宠悬停任务面板、Codex 任务状态同步、输入框加号能力菜单

## 1. 冻结规则

本文件只记录 v2.5 新增范围，不修改 v1.0 至 v2.4 的冻结基线。生成 SHA-256 校验并设为只读后不得原地修改；后续变更必须建立更高版本基线。

## 2. 多任务悬停面板

- 修复桌宠悬停摘要只能展示一个 Codex 任务的问题。
- 悬停桌宠后，以一个紧凑列表同时展示最多 5 个近期 Codex 桌面任务；正在执行或等待操作的任务优先，其次按最近更新时间排序。
- 每个任务独立显示任务标题和真实状态：正在思考、等待操作、已完成、已停止或失败。
- 每一行提供“在 Codex 中打开”入口，必须打开该行对应的任务，不得始终跳转到最近任务。
- 多任务列表高度随任务数量动态变化，并根据桌宠所在屏幕的可用空间智能向上或向下展开；不得遮挡、裁切或重新引入透明矩形承载边。
- 任务状态至少每 1.5 秒同步一次。一个任务的状态变化不得覆盖、删除或错误复用其他任务的状态。
- 桌宠工作动画在任一可见任务处于思考或等待状态时持续；只有全部可见任务均非进行中时才结束。
- 点击桌宠时，多任务面板沿用已有“先收起、再展开输入框”的连续动画。

## 3. 官方式加号能力菜单

- 保留 v2.4 的文件、文件夹、照片与截屏入口。
- 通过 Codex App Server `skills/list` 读取本机当前可用技能，在“技能与插件”分组展示名称与简介；选择后以官方 `skill` 输入项和 `$技能名` 标记提交。
- 通过 Codex App Server `app/list` 读取当前账号可访问且已启用的应用，在“应用”分组展示名称与简介；选择后以官方 `mention` 输入项和 `$应用标识` 标记提交。
- 已选择的技能和应用与附件一起显示为可移除标签，允许只选择能力后输入问题，也允许能力、附件和文字组合发送。
- 菜单只展示 App Server 实际返回的能力，不伪造不可调用入口。官方未向 App Server 开放的 ChatGPT 历史对话附加能力不在本版伪实现；最近 Codex 任务由多任务面板负责展示与跳转。
- 已选能力随本次发送清空，未发送时隐藏再展开输入框仍保留。

## 4. 协议、安全与兼容

- 多任务数据只读取本机 Codex `thread/list` 和只读 rollout 状态，不创建、修改、归档或删除桌面任务。
- 技能和应用均通过官方 App Server 返回的标识与路径调用，不扫描或猜测账户能力。
- 延续 `approvalPolicy = never`、只读 sandbox、双 App Server 和无冲突交接设计。
- 老版本 `sessions.json` 继续可解码；能力引用元数据使用兼容的可选字段。

## 5. 验收与交付

- 自动测试覆盖多任务排序与上限、任务独立状态、失败状态、动态面板高度、技能/应用输入映射及旧会话兼容。
- 实机验证多任务面板同时出现多行、各行跳转目标正确、状态变化不互相覆盖，以及技能/应用菜单来自真实 App Server 数据。
- 完成 Swift 测试、Xcode 构建、Release 构建、签名和全部冻结基线哈希校验。
- 应用版本升级为 0.2.5（构建号 7），更新 README、验证报告、应用包、源码压缩包并创建本地 Git 提交；本轮不自动推送远端。

## 6. 官方依据

官方 OpenAI 文档说明 `thread/list` 返回线程运行状态并支持按 `recency_at` 排序；`skills/list` 可读取当前工作目录的技能；`app/list` 可读取当前账号可访问及已启用的应用；`turn/start.input` 可用 `skill` 和 `mention` 输入项显式调用能力：<https://learn.chatgpt.com/docs/app-server>。
