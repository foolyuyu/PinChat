# PinChat v3.12 桌宠交互润色需求基线（锁定稿）

锁定日期：2026-09-18（Asia/Shanghai）

本文件记录桌宠转头、待机、窗口动效、连接期输入和回答窗脱离吸附的优化要求。v1.0 至 v3.11 其他冻结需求继续有效；本文件不得回改既有基线，只允许后续版本追加。

## 1. 键入光标注视

- 输入框获得焦点后，桌宠继续注视真实文字插入光标，而不是鼠标指针。
- 目标方向变化时，不得在 16 向姿态之间直接跳变；每约 50 毫秒沿最短路径移动一个方向格。
- 首次进入输入框时从中性姿态逐格转向目标，避免输入条展开的一刻突然扭头。
- 开启 macOS“减少动态效果”时允许直接切换到目标方向。

## 2. 待机动作

- 历史回答文本不再被视为一次持续中的完成提醒，恢复应用或空闲时使用官方待机动画。
- 挥手素材保留给后续明确、短暂的完成提醒；其播放速度由 0.11 秒/帧降至 0.22 秒/帧，避免过度显眼。

## 3. 窗口动效

- 输入条展开由 0.17 秒调整为 0.24 秒，收回由 0.16 秒调整为 0.22 秒。
- 浮动状态/回答面板展开由 0.22 秒调整为 0.28 秒，状态卡收回由 0.13 秒调整为 0.20 秒。
- 原有从两侧向中间收拢的几何和防止旧动画误隐藏新窗口的修订保护保持不变。

## 4. 连接期输入

- 显示“正在连接本机 Codex…”期间，文字输入框保持可编辑，用户可以提前填写并保留草稿。
- 服务就绪前发送按钮继续禁用；连接成功后已有草稿自动进入可发送状态。
- 连接期输入不得绕过登录、服务可用性或任务运行中不可重复发送的约束。

## 5. 回答窗脱离吸附

- 完整回答窗口首次被用户从桌宠吸附位置拖出时，桌宠旁的提醒/状态卡自动收回。
- 被拖出的回答窗口继续显示并可拖动、缩放和追问；任务、会话及回答内容不得被重置。
- 程序自身调整回答窗口位置不触发该行为，持续拖动过程也不得重复启动收回动画。

## 6. 范围边界

- “小输入框每次新建对话、统一任务队列、简单回答自动展开、完成灵光提示、悬停统一展示”等新流程本轮只形成确认稿，不在 v3.12 中实现。
- 未经用户确认不得提前合并现有的两套过程展示逻辑。

## 7. 验收标准

- 输入框打开后桌宠以连续方向帧转向插入光标，跨 0/15 边界时仍走最短路径。
- 空闲桌宠不再因保存过的回答持续快速挥手。
- 输入与状态窗口的展开、收回肉眼可见地更从容，但不拖沓。
- 连接中可键入草稿，服务就绪前不能发送。
- 吸附回答窗被手动拖离后回答窗保留、提醒卡收回。
- 自动测试、Debug/Release 构建、签名及 v1.0 至 v3.12 全部冻结需求校验通过。
