# PinChat Codex 交接修复需求基线 v2.3（冻结）

状态：已确认、实施中、冻结  
确认日期：2026-09-15  
适用范围：PinChat 对话任务交接、Codex 桌面任务状态观察、App Server 生命周期

## 1. 冻结规则

本文件只记录 v2.3 对“在 Codex 中打开”占用提示的修复，不替换或修改 v1.0、v1.1、v2.0、v2.1、v2.2 基线。生成 SHA-256 校验并设为只读后不得原地修改；后续变更必须建立更高版本基线。

## 2. 问题定义

- 从 PinChat 完成卡或回答面板点击“在 Codex 中打开”后，Codex 不得再显示“已在另一个应用中打开，请先在那边关闭会话，才能在这里继续”。
- 交接成功后必须打开同一个 Codex 任务，并可立即在 Codex 桌面应用中继续正常对话。
- 修复不得移除 v2.2 的桌面任务悬停状态同步。

## 3. 双通道架构

- 使用独立的“对话 App Server”处理账号、配置、PinChat 提问、流式回答、对话同步及线程订阅。
- 使用独立的“活动观察 App Server”只读调用 `thread/list` 并读取本机任务记录，用于桌面任务状态摘要。
- 活动观察通道不得恢复、订阅、发送、打断或接管任何对话线程。
- 两个通道的生命周期相互独立；对话通道停止不得中断活动观察通道。

## 4. 交接流程

1. 仅允许在当前回答完成或停止后发起交接。
2. 对话通道发送 `thread/unsubscribe`，取消 PinChat 对当前线程的订阅。
3. 无论取消订阅请求成功或失败，均彻底终止该对话 App Server，并等待进程退出；只有退出完成后才执行下一步。
4. 使用 `codex://threads/<thread-id>` 打开原任务。
5. 打开成功后 PinChat 切换到新的空白快速会话；活动观察通道继续运行。
6. 用户再次打开 PinChat 输入框时，按需重启新的对话通道，但不得自动恢复或重新订阅已交接任务。
7. 若 Codex URL 打开失败，则恢复对话通道和原 PinChat 会话，并给出明确错误提示。

## 5. 验收与交付

- 自动化测试覆盖双通道角色、交接后仅保留活动观察通道、对话通道按需重启以及原任务 ID 保持不变。
- 完成 Swift 测试、Xcode 构建、Release 构建、Info.plist、签名和全部冻结基线哈希校验。
- 实机检查：PinChat 提问完成后点击 `↗`，Codex 打开同一任务，不出现占用提示，并能继续输入；桌宠悬停仍可显示桌面任务状态。
- 应用版本升级为 0.2.3（构建号 5），更新 README、验证报告、应用包和源码压缩包。
- 完成新的本地 Git 提交；除非用户另行要求，本轮不自动推送远端。

## 6. 官方协议依据

Codex App Server 的 `thread/start` 会自动订阅线程；`thread/unsubscribe` 只取消当前连接的订阅，最后一个订阅者离开后线程仍存在无订阅活动宽限期。v2.3 因此在取消订阅后终止对话 App Server，消除与 Codex 桌面端接管同一线程的竞争。依据：[Codex App Server API](https://learn.chatgpt.com/docs/app-server#api-overview)。
