# PinChat v3.8 任务卡交互整理需求基线（锁定稿）

锁定日期：2026-09-18（Asia/Shanghai）

本文件记录 PinChat v3.8 的增量需求。v1.0 至 v3.7 已冻结需求继续有效；本文件不得回改既有基线，只允许后续版本追加。

## 1. 完成状态去重

- 当前 PinChat 问答完成后点击 `✓`，必须同时确认同一 Codex 线程在桌面任务观察通道中的完成回执。
- 再次悬停桌宠时，同一完成结果不得以“完成后继续展示 30 秒”的形式重复出现。
- 若桌面任务观察器晚于问答卡收到完成回执，明确确认仍必须跨越该竞态并过滤下一次对应回执。
- 其他线程的完成状态不得因本次确认被误删。

## 2. 桌面任务卡

- 每一整行任务卡都是打开对应 Codex 任务的入口，并提供清晰、克制的悬停和按下反馈。
- 删除右侧重复的斜向打开箭头。
- 正在思考的任务提供补充入口；点击后在原行内显示紧凑输入框。
- 提交补充时，通过 Codex 官方现有任务深链打开准确线程，并把内容预填到该任务的输入区，不创建新任务。
- 已完成任务左侧 `✓` 的单项确认语义继续遵守 v3.7。

## 3. 展开回答窗口

- 顶部左侧删除星光图标、会话标题以及“已吸附 / 自由窗口”状态标签。
- 顶部仅保留右侧的新建对话和关闭按钮，并缩减顶部留白。

## 4. 官方控制边界

- 官方桌宠的一键停止与后台补充直接调用 Codex Desktop 当前进程所持有的活动 turn。
- PinChat 的独立桌面任务观察连接无法取得该 active writer；不得用无效请求或伪状态假装任务已经停止。
- PinChat 自己发起且仍在生成的回答继续支持真实停止；Codex Desktop 自己持有的任务需打开准确任务后使用官方停止按钮。
- 不为模拟点击引入 macOS 辅助功能权限，避免增加系统授权和脆弱的坐标自动化。

## 5. 验收标准

- 当前问答确认后，同线程完成记录不再通过桌面任务卡返场。
- 点击任务行空白、标题或状态均打开准确任务；右侧不再出现斜向箭头。
- 点击思考任务的补充按钮可输入内容，提交后 Codex 打开准确线程并预填原文。
- 展开回答窗口左上角保持空白、简洁。
- 自动测试、Debug/Release 构建、签名及 v1.0 至 v3.8 全部冻结需求校验通过。
