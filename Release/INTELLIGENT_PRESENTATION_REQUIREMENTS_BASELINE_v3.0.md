# PinChat 智能对话与任务展示需求基线 v3.0（冻结）

状态：已确认、实施中、冻结  
确认日期：2026-09-16  
适用范围：PinChat 发起的 Codex 对话、回答窗口与任务进度卡

## 1. 冻结规则

本文件只记录 v3.0 新增范围，不修改 v1.0 至 v2.5 的冻结基线。生成 SHA-256 校验并设为只读后不得原地修改；后续变更必须建立更高版本基线。

## 2. 智能展示流程

- 用户从 PinChat 发送请求后，本轮初始状态为“判断中”，先显示紧凑进度卡。
- 不依赖问题关键词猜测类型，以本机 Codex App Server 返回的真实执行事件为主要依据。
- 若本轮没有执行型行为，并开始产生正式回答内容，自动展开回答窗口，直接显示流式回答并允许继续追问。
- 若本轮出现命令执行、文件变更、工具调用、网页检索、图片查看、子任务、等待或审批请求，保持紧凑进度卡，不自动展开大回答窗口。
- 执行型行为优先级最高；一旦本轮被识别为工作任务，本轮不再自动降级为普通对话，避免窗口反复跳动。
- 若正式回答先于执行型事件出现，可先展开回答窗口；后续一旦出现执行型事件，回答窗口自动收回并恢复进度卡。

## 3. 连续交互与手动控制

- 自动展开的回答窗口沿用现有吸附、拖动、缩放、关闭、继续追问、新建对话和在 Codex 中打开能力。
- 在已展开回答窗口中继续提问时，窗口保持可见；若追问升级为工作任务，再自动切回进度卡。
- 工作任务完成后不强制弹出回答窗口；用户仍可通过进度卡的展开按钮手动查看最终回答。
- 用户手动关闭自动展开的回答窗口后，同一轮后续文字增量不得反复将其打开。
- 新建对话时清空上一轮的类型判断，不影响历史消息和 Codex 线程交接逻辑。

## 4. 兼容与边界

- 继续使用本机 Codex 登录、额度、模型、推理强度与人格，不接入额外 AI API。
- 保留双 App Server、全屏置顶、桌面任务悬停、多任务完成回执、附件、透明材质及现有窗口位置规则。
- 事件识别必须忽略普通用户消息、推理文本和中间说明；这些内容本身不得误判为工作任务。
- 老版本会话数据继续兼容，不向持久化会话格式加入必填字段。

## 5. 验收与交付

- 自动测试覆盖普通回答自动展开、执行型事件升级、工作模式不可降级及 App Server 事件分类。
- 完成 Swift 测试、Release 构建、签名和全部冻结基线哈希校验。
- 应用版本升级为 0.3.0（构建号 8），更新 README、验证报告、应用包和源码压缩包；本轮不自动推送远端。
