# PinChat 优化需求基线 v1.1（冻结）

状态：已确认、实施中、冻结  
确认日期：2026-09-15  
适用范围：PinChat macOS 初版的首轮体验优化

## 1. 冻结规则

本文件记录用户确认的首轮优化需求。文件冻结后不得原地修改；后续新增、删除或变更需求必须新建更高版本的优化需求基线，并保留本文件及其 SHA-256 校验文件。

## 2. 优化目标

### OPT-01 小窗顶部留白

- 去除标题栏区域造成的过量顶部空白。
- 顶部仅保留足以让工具栏内容舒适呼吸的少量间距。
- 收起、置顶、账号、新建对话及“在 Codex 中打开”按钮仍须完整可见、可点击。

验收标准：小窗内容延伸至透明标题栏区域，工具栏上方视觉留白约为 8pt，不再出现截图中的大块空白。

### OPT-02 悬浮泡拖动跟手性

- 拖动期间悬浮泡应持续跟随鼠标屏幕坐标。
- 鼠标在悬浮泡内的抓取位置应保持不变，不得在拖动中跳动或产生明显滞后。
- 松手后继续保留贴边、多屏限制和位置持久化能力。

验收标准：从悬浮泡任意位置按下并拖动时，鼠标与悬浮泡的相对偏移保持恒定。

### OPT-03 悬浮泡透明方框

- 悬浮泡窗口及 SwiftUI 宿主背景必须真正透明。
- 调整阴影范围，避免阴影在矩形窗口边界被裁切并形成透明方框观感。
- 悬浮泡仍保持圆形、描边、渐变和轻量阴影。

验收标准：浅色和深色桌面上均只看到圆形悬浮泡及自然阴影，不出现外围正方形边界。

### OPT-04 用户消息外观

- 用户发出的消息使用 macOS 当前控制强调色作为气泡背景。
- 文本使用适配强调色背景的高对比度前景色。
- 默认系统设置下应与本机 Codex 的蓝色用户消息气泡保持一致；用户修改系统强调色后应随系统更新。

验收标准：默认强调色环境下，PinChat 用户消息显示为蓝色圆角气泡、白色文字。

### OPT-05 回答内容去重

- PinChat 只把 Codex 的最终回答展示为正文，不把 commentary 阶段内容再次拼接到最终回答。
- 流式阶段按 `itemId` 关联消息，避免不同代理消息项目混写。
- 以 App Server 的 `item/completed` 最终文本覆盖流式累积文本，确保完成态内容权威且不重复。
- 后台历史同步忽略 commentary 阶段的代理消息。

验收标准：一次询问只显示一份最终回答；完成后的文本与 Codex App Server 返回的最终 `agentMessage` 一致。

### OPT-06 在 Codex 中打开并继续对话

- 点击右上角按钮后，先停止 PinChat 对当前线程的轮询，再调用 `thread/unsubscribe` 释放订阅。
- 随后终止 PinChat 自己启动的 App Server 子进程，确保线程不再被另一个客户端占用。
- 完成释放后再通过 `codex://threads/<thread-id>` 打开 Codex。
- Codex 打开后应进入同一线程，且用户可直接继续对话，不出现“已在另一个应用中打开”的提示。
- 成功交接后，PinChat 下次打开时使用新空白会话并按需重启本地服务，避免重新抢占已交给 Codex 的线程。
- 当前仍在生成回答时不执行交接，必须先完成或停止生成。

验收标准：已完成回答的会话可从 PinChat 交接到 Codex；Codex 中保留原对话内容，可立即发送下一条消息。

## 3. 保持不变的产品边界

- PinChat 仍是 macOS 原生 Codex 置顶伴随小窗，不是独立聊天主应用。
- 小窗内不增加历史会话入口。
- 继续使用用户的官方 ChatGPT 登录与本机 Codex 配置，不接入 API Key。
- 新对话继续继承本机 Codex 的模型、推理强度和人格。
- 快捷键、可关闭的常驻悬浮泡、普通全屏 Space 置顶能力继续保留。
